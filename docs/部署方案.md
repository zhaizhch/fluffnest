# 绒窝 FluffNest · 部署与 GitHub 分发

> 主渠道：**GitHub Releases**（所有用户下载 DMG / ZIP）  
> 标识符：`com.fluffnest.deskpet`  
> 用户文档：[用户安装指南](./用户安装指南.md)

---

## 1. 分发架构

```
开发者推送 tag v0.1.0
        ↓
GitHub Actions (macos-14)
  ├─ 构建 aarch64 → DMG + ZIP + SHA256
  └─ 构建 x86_64  → DMG + ZIP + SHA256
        ↓
自动创建 GitHub Release（附安装说明）
        ↓
用户打开 Releases 页下载对应芯片安装包
```

| 产物 | 用途 |
|------|------|
| `FluffNest_*_aarch64.dmg` | Apple Silicon 用户（主推） |
| `FluffNest_*_x86_64.dmg` | Intel Mac 用户 |
| 同名 `.zip` | 不便用 DMG 时的备选 |
| `SHA256SUMS.txt` | 完整性校验 |

## 2. 一次性：创建 GitHub 仓库

在项目根目录（已有代码、尚未关联 remote 时）：

```bash
# 1) 首次提交
git add -A
git commit -m "feat: initial FluffNest desktop pet"

# 2) 创建公开仓库并推送（仓库名建议 fluffnest）
gh repo create fluffnest --public --source=. --remote=origin --push

# 或已有空仓库：
# git remote add origin https://github.com/zhaizhch/fluffnest.git
# git push -u origin main
```

推送后 Releases 地址：

`https://github.com/zhaizhch/fluffnest/releases`

## 3. 本地开发与构建

```bash
npm install
npm run tauri:dev          # 开发
npm run tauri:build        # 仅 .app
npm run release:package    # 当前机器架构的完整发布包 → release/v*
```

环境：macOS 12+、Node 20+、Rust stable、Xcode CLT。

## 4. 发布到 GitHub（推荐流程）

### 4.1 改版本号

```bash
chmod +x scripts/*.sh
./scripts/bump-version.sh 0.1.0   # 同步 package.json / tauri.conf / Cargo.toml
```

### 4.2 提交并打 tag

```bash
git add -A
git commit -m "chore: release v0.1.0"
git tag v0.1.0
git push origin main
git push origin v0.1.0
```

### 4.3 自动发布

推送 `v*` tag 后，工作流 [`.github/workflows/release.yml`](../.github/workflows/release.yml) 会：

1. 在 `macos-14` 上分别构建 Apple Silicon / Intel 包  
2. 生成 DMG、ZIP、校验和  
3. 创建同名 **GitHub Release** 并上传 Assets  

也可在 Actions 页手动 **Run workflow**。

### 4.4 本地打包后手动上传（备用）

无 CI 或需自签时：

```bash
./scripts/package-release.sh aarch64
./scripts/package-release.sh x86_64   # 需在可交叉编译的 Mac 上

gh release create v0.1.0 \
  release/v0.1.0/*.dmg \
  release/v0.1.0/*.zip \
  release/v0.1.0/SHA256SUMS_*.txt \
  --title "绒窝 FluffNest v0.1.0" \
  --notes-file docs/用户安装指南.md
```

## 5. 用户侧（你要告诉下载者的话）

完整文案见 [用户安装指南](./用户安装指南.md)。摘要：

1. 到 Releases 下载对应芯片的 **DMG**  
2. 拖到「应用程序」  
3. 若无法打开：右键 → 打开，或 `xattr -cr /Applications/FluffNest.app`

**未签名包**在他人电脑上几乎总会触发 Gatekeeper，安装指南必须随 Release 一起提供。

---

## 6. 签名与公证（公测 / 正式对外建议）

开源首发可用未签名包 + `xattr` 说明。若希望「双击即开、无警告」：

1. Apple Developer 账号  
2. `Developer ID Application` 证书  
3. 构建前配置：

```bash
export APPLE_SIGNING_IDENTITY="Developer ID Application: ..."
export APPLE_ID="..."
export APPLE_PASSWORD="xxxx-xxxx-xxxx-xxxx"
export APPLE_TEAM_ID="..."
```

4. 对 DMG 执行 `notarytool submit` + `stapler staple`（详见 Tauri 签名文档）

可将证书以 GitHub Secrets 注入 CI（后期增强）。当前 CI **默认不签名**，便于先上架下载。

## 7. Release Checklist

- [ ] 版本号三处一致（`bump-version.sh`）
- [ ] README / 安装指南链接指向正确仓库
- [ ] `git tag vX.Y.Z` 已推送
- [ ] Actions Release 工作流成功（绿勾）
- [ ] Release Assets 含 aarch64 + x86_64 的 dmg/zip 与 SHA256
- [ ] 干净账号试装：拖入应用程序 + Gatekeeper 步骤
- [ ] （可选）签名公证后再发正式版

## 8. 自动更新（后期）

首版靠用户手动下新 Release。后续可接：

- [Tauri Updater](https://v2.tauri.app/plugin/updater/) + GitHub Releases 作为更新源  
- 需签名更新包，并控制检查频率（避免打扰专注模式）
